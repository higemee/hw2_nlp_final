# ДЗ 2. Генерация кода по текстовой задаче

Encoder-decoder Transformer, обученный с нуля на датасете
[`SlavaYus/tinysms_qa_12m`](https://huggingface.co/datasets/SlavaYus/tinysms_qa_12m): по тексту математической задачи
модель генерирует программу `solve()`, результат которой сравнивается с эталонным ответом.

**pass@1 на публичном лидерборде: 77.5%.** Генерация ответов для теста занимает ~85 секунд на одной T4.

## Структура репозитория

```
src/
  prepare.py      подготовка данных: скачивание, токенизатор, фильтрация, токенизация
  codefmt.py      компактный формат целевой программы и сборка программы из него
  data.py         токенизированный датасет и батчи по бюджету токенов
  model.py        модель и генерация с KV-кэшем
  train.py        обучение (DDP, fp16, расписание LR по времени)
  generation.py   генерация программ для списка вопросов
  execute.py      исполнение программ в песочнице, сравнение ответов, голосование
  infer.py        генерация ответов для теста с ограничением по времени
notebooks/
  01_prepare.ipynb    подготовка данных (Kaggle, CPU)
  02_train.ipynb      обучение (Kaggle, 2 x T4)
  03_inference.ipynb  генерация ответов для теста (одна T4, <= 180 с)
tests/              проверка KV-кэша, формата программ и песочницы
```

## Данные (`src/prepare.py`)

1. Train — 11.84M пар «вопрос → программа» из TinyGSM (60 parquet-шардов), test — 1919 вопросов.
2. **Валидация:** 2000 случайных вопросов последнего шарда; ответ — результат исполнения эталонной программы.
   Остаются вопросы с числовым ответом (~1980), все копии этих вопросов удаляются из train.
3. **Компактный формат цели** (`src/codefmt.py`). Все эталоны имеют вид `def solve() -> int:` + тело +
   `return result`. Модель учится генерировать только тело функции без комментариев, пустых строк и отступа
   функции; программа собирается обратно детерминированно. Средняя длина цели — 61 токен вместо ~72.
4. **Токенизатор:** byte-level BPE на 8192 токена, общий для вопросов и кода, каждая цифра — отдельный токен
   (числа переносятся из вопроса в код по цифрам). Словарь 16k сокращает длины только на ~2%.
5. **Фильтрация:** программа, собранная из компактной цели, исполняется в песочнице; пары, где она не возвращает
   число (кортежи, строки, ошибки — 322k, 2.7%), удаляются, так как в тесте только числовые ответы.
6. Вопросы и цели токенизируются в плоские массивы `uint16` со смещениями.

Итого 11.51M пар, 577M токенов вопросов и 705M токенов целей на эпоху (средняя длина 50 и 61).

## Модель (`src/model.py`)

| | |
|---|---|
| архитектура | encoder-decoder Transformer, pre-norm |
| слои | 6 в энкодере, 8 в декодере |
| d_model / головы | 512 / 8 |
| FFN | SwiGLU, скрытый размер 1408 |
| нормализация | RMSNorm |
| позиции | RoPE в self-attention энкодера и декодера |
| эмбеддинги | общие для энкодера, декодера и выходного слоя |
| словарь | 8192 |
| параметры | 57.6M |

Внимание считается через `F.scaled_dot_product_attention`. Лосс считается только на непаддинговых токенах цели.
Генерация батчевая, с KV-кэшем self-attention, K/V cross-attention считаются один раз; завершившиеся
последовательности удаляются из батча.

## Обучение (`src/train.py`)

- Kaggle, 2 x T4, DDP; fp16 autocast + GradScaler.
- Батчи по бюджету в 32768 токенов (с паддингом) на GPU. Внутри кусков по 200k примеров данные сортируются по
  корзине длины цели и длине вопроса, поэтому 91% токенов в батче — не паддинг. Датасет целиком читается в RAM.
- AdamW (β = 0.9, 0.95, weight decay 0.1), clip 1.0, lr 1e-3.
- Расписание warmup-stable-decay, привязанное ко времени: 1000 шагов warmup, затем постоянный lr и линейный спад
  до 1% в последние 25% бюджета (10 часов). Так обучение завершается вовремя независимо от скорости.
- Каждые 45 минут — val loss и pass@1 жадной генерации на 500 вопросах валидации, каждые 30 минут — чекпоинт.
- Итого 43.9k шагов, около 2 эпох.

## Генерация ответов (`src/infer.py`)

1. Жадное декодирование для всех вопросов (fp16, батчи по 512 вопросов, отсортированных по длине).
2. Пока позволяет время — 8 сэмплов на вопрос с температурой 0.7. Все кандидаты (жадный + сэмплы) исполняются
   в песочнице (`src/execute.py`: отдельные процессы, таймаут, лимит памяти), выбирается программа с самым частым
   числовым ответом, при равенстве — жадная.
3. Результат — `submission.jsonl`, по строке `{"code": "..."}` на задачу.

Время на T4: загрузка 12 с, жадная генерация 13 с, сэмплирование 51 с, исполнение 9 с — всего ~85 с.
Сэмплирование останавливается автоматически, если следующий батч не укладывается в 160 секунд.

## Результаты и эксперименты

| | pass@1 |
|---|---|
| публичный лидерборд | **77.5%** |
| валидация, жадная генерация | 51.6% |
| валидация, голосование по 8 сэмплам | 54.8% |

Значения на валидации ниже, чем на тесте: в обучающем пуле у одного вопроса бывает несколько эталонных программ,
в том числе неверных, а ответ валидации берётся из одной из них. Поэтому валидация использовалась только
для сравнения вариантов между собой.

| эксперимент | результат |
|---|---|
| BPE 8k и 16k | длины почти одинаковые, выбран 8k |
| компактный формат цели | цель короче на ~20%, обратное преобразование без потерь (проверено исполнением) |
| сортировка батчей по корзинам длины | доля не-паддинга 72% → 91% |
| датасет в RAM вместо memmap с диска Kaggle | 5k → 94k токенов/с на 2 x T4 |
| голосование по 8 сэмплам вместо жадной генерации | 51.6% → 54.8% на валидации |
| декодер 8 слоёв вместо 6 | выбран из оценки бюджета вычислений (за 10 ч ~2 эпохи вместо ~2.6), отдельно не сравнивался |

## Запуск

```bash
pip install -r requirements.txt
python src/prepare.py --out data/prepared
torchrun --nproc_per_node=2 src/train.py --data_dir data/prepared --out_dir runs/main --time_budget_h 10
python src/infer.py --model_dir runs/main --input test.parquet --out submission.jsonl  # test split датасета
python tests/test_model.py && python tests/test_codefmt.py
```

На Kaggle те же шаги выполняются ноутбуками из `notebooks/`.
